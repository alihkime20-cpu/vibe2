# المعمارية التقنية

## النطاق

هذه المرحلة تبني أساس موسوعة عالمية متعددة اللغات دون توليد محتوى جماعي أو بناء واجهة نهائية كبيرة. التطبيق عبارة عن واجهة Vite/React مستقلة، بينما PostgreSQL عبر Supabase هو مصدر البيانات الرئيسي. لا يعتمد الكود الجديد على OAuth أو Forge أو تخزين Manus، ويمكن تشغيله محليًا أو على استضافة Node/Vite قياسية.

## القرارات المعمارية

| القرار       | التنفيذ                                                               | السبب                                                                                                                 |
| ------------ | --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| هوية الموضوع | جدول `topics` بصف واحد منطقي لكل موضوع                                | يمنع تكرار الكيان العربي والإنجليزي، ويجعل إضافة لغات جديدة إضافة صفوف ترجمة فقط                                      |
| المقال       | جدول `articles` مرتبط واحدًا بواحد مع `topics`                        | يفصل هوية المقال عن المحتوى اللغوي ودورة النشر                                                                        |
| الترجمة      | `article_translations` مع قيد فريد `(article_id, language_code)`      | يضمن ترجمة واحدة لكل لغة ويتيح إضافة الفرنسية والإسبانية والتركية دون تعديل المخطط                                    |
| حالة النشر   | حالة مستقلة لكل ترجمة                                                 | قد تنشر النسخة الإنجليزية قبل العربية أو العكس، مع دعم `draft → review → published → archived`                        |
| التاريخ      | `article_revisions` كسجل لقطات غير قابل للتكرار لكل إصدار             | يتيح المراجعة والرجوع والتدقيق دون الكتابة فوق التاريخ                                                                |
| التصنيفات    | `categories.parent_id` مع جدول ترجمة                                  | يدعم شجرة الأب/الابن مع أسماء ووصف مستقلين لكل لغة                                                                    |
| البحث        | PGroonga على نص مشتق من العنوان والملخص والمحتوى والكلمات المفتاحية   | يطابق العربية والإنجليزية بصورة أفضل من محلل `english` المدمج؛ وهو امتداد متاح في مشروع Supabase الحالي               |
| التخزين      | جدول `media` وbucket اختياري `encyclopedia-media` في Supabase Storage | يفصل metadata عن الملف، ويظل مسار التخزين قابلًا للنقل                                                                |
| الوصول العام | RLS بسياسات قراءة للمنشور فقط                                         | لا يحتاج الزائر إلى تسجيل دخول، بينما تبقى الكتابة والإصدارات الخاصة محمية وتتم لاحقًا عبر service role أو دور تحريري |

## طبقات التشغيل

```text
React/Vite static client
        │  Supabase JS / PostgREST / RPC
        ▼
Supabase PostgreSQL + RLS + PGroonga
        │
        ├── Supabase Storage (encyclopedia-media)
        └── future editorial worker / service-role ingestion
```

الواجهة الحالية ليست لوحة تحرير ولا تنشئ مقالات. وهي تعرض حالة الاتصال فقط لتقليل مساحة المرحلة الأولى، مع ترك API العام في Supabase جاهزًا لاستخدام صفحات الموسوعة لاحقًا.

## قابلية النقل

الإعدادات الوحيدة المطلوبة للتطبيق هي `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`. لا توجد أسرار داخل المستودع. أما عمليات الكتابة والتحرير المستقبلية فتستخدم `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` على خادم آمن أو وظيفة Edge، ولا يجوز وضع service-role key في المتصفح.

يتم حفظ كل DDL في `database/migrations/` بصيغة SQL قياسية. يمكن تطبيقها من Supabase Dashboard أو CLI أو أي اتصال PostgreSQL آمن، ثم إجراء backup/restore عبر أدوات PostgreSQL القياسية. هذا يحقق مطلب عدم الارتباط بخدمة Manus، مع الاحتفاظ بمزايا Supabase الخاصة بقاعدة البيانات والتخزين.

## المصادر التقنية

توضح وثائق Supabase أن PGroonga يدعم نطاقًا أوسع من اللغات والشخصيات من البحث النصي الأصلي في PostgreSQL، وتستخدم فهرس `USING pgroonga` والعامل `&@~` للبحث متعدد اللغات [1]. أما البحث النصي الأصلي في PostgreSQL فيعتمد على configurations وقواميس لغوية؛ لذلك لا يُستخدم وحده كطبقة البحث الرئيسية للعربية هنا [2].
